# Wayfinder

Make the route to a defined outcome visible before starting execution. Use this for efforts that are too large or uncertain to resolve in one session. Keep the map as a compact index, with details in linked decision records or tickets.

## Create the map

1. State the destination in one or two sentences. Define what will be true when planning is complete.
2. Record the scope, key constraints, relevant skills, and known source systems.
3. Separate decisions from implementation tasks. A decision asks a question whose answer changes the route. An implementation task delivers an already-decided outcome.
4. Add a ticket or note for each decision that can be stated clearly now. Record one question per item and link its prerequisites. Keep future questions that are not yet precise in an “Unresolved later” section.
5. Record decisions in their own tickets or notes. Keep the map to a short index of decisions, unresolved questions, and work outside the destination.

Use the project's issue tracker when it is available and suitable. Otherwise, keep the map and decision notes in the project's existing planning format. Follow the host's access rules and the user's authorization before creating or changing external items.

## Work through the map

1. Read the map first, then open only the related notes and sources needed for the next decision.
2. Choose an unblocked decision. Claim it in the tracker when that feature is available.
3. Resolve it with evidence or a focused discussion. Keep research and human preference distinct; do not answer on behalf of the user when their choice is required.
4. Record the answer, rationale, and source links in the decision record. Update the map with a short pointer.
5. Add newly clear decisions, update dependencies, and remove obsolete questions. Keep the unresolved-later section limited to in-scope questions that cannot yet be stated precisely.

Independent research can run in parallel when the tools and task boundaries support it. Resolve judgment calls with the relevant human. Stop when the route is clear and no decision blocks execution. Continue into implementation only when the user asks for it.

## Keep the map useful

- Refer to items by their names and link them; avoid an index made of bare ticket IDs.
- Keep each decision in one canonical place. The map summarizes and points to it.
- Revisit scope when a newly discovered task falls beyond the destination. Record that boundary so it does not return as an unresolved question.
- Do not pre-plan details that depend on open decisions. Let the map grow as answers make the next questions precise.
